# Skill Builder V1.0

## 目标

将用户关于 Skill 的初步想法整理为清晰、可复用的基础 Skill 定义，并生成可直接保存和继续完善的 `Skill.md`。

## 工作方式

### 1. 收集需求

先检查用户已经提供的信息，只询问尚未明确且确有必要的内容。全部访谈最多提出 5 个问题，围绕：

1. **Skill 目标**：这个 Skill 想解决什么问题？
2. **使用场景**：这个 Skill 主要用于什么场景？
3. **核心功能**：这个 Skill 需要完成哪些主要功能？
4. **输入**：用户需要提供哪些文本、图片、文件、链接或数据？
5. **输出**：这个 Skill 最终需要生成什么结果？

提问时遵循以下要求：

- 优先确认核心功能。
- 不重复询问用户已经说明的信息。
- 每个问题使用简单、非技术化的表达。
- 信息足够时立即停止提问，不必问满 5 个问题。
- 信息不足以形成可执行定义时，不自行虚构关键需求。

### 2. 整理 Skill 信息

根据用户回答整理：

- **Skill 名称**：简洁、明确，能够体现核心能力。
- **Skill 目标**：说明要解决的问题和预期价值。
- **使用场景**：说明适用的任务、用户或环境。
- **核心功能**：使用具体、可执行的描述列出主要能力。
- **输入**：明确用户需要提供的信息及必要格式。
- **输出**：明确最终交付结果及基本形式。

如果存在轻微缺失但不影响基础版本，可采用最小且合理的假设，并明确标注；如果缺失会显著改变 Skill 的用途或功能，则继续提问。

### 3. 生成基础 Skill.md

先输出整理后的 Skill 设计信息，再输出一份完整的 Markdown 内容。生成结果至少包含：

```markdown
# Skill Name

## Description

说明 Skill 是什么、解决什么问题，以及适用范围。

## Function

- 功能 1
- 功能 2
- 功能 3

## Input

- 输入 1
- 输入 2

## Output

- 输出 1
- 输出 2

## Usage Scenario

说明 Skill 的典型使用场景。
```

根据实际需求增减功能、输入和输出条目，不保留无内容的占位符。

## 输出格式

最终输出分为两个部分：

1. **Skill 设计信息**：名称、目标、使用场景、核心功能、输入和输出。
2. **完整 Skill.md**：放入 Markdown 代码块，确保用户可以直接复制保存。

## V1.0 范围

默认只生成 Skill 的基础架构和功能定义，不加入以下高级内容：

- 复杂 Workflow
- Eval 或测试评估体系
- 安全策略
- 工具或 API 调用设计
- 脚本、参考资料或资源目录

只有在用户主动要求时，才扩展上述内容。

## 质量检查

生成前确认：

- Skill 目标是否明确。
- 使用场景是否清楚。
- 核心功能是否具体、可执行。
- 输入和输出是否明确。
- 内容是否具有复用价值。
- 是否保持在用户要求的基础版本范围内。
